Shift-Left Engineering · Context7 for Security

KB Anti-Vibe-Coding System

Transformer KB en un système d'ingénierie de sécurité proactif façon Context7 : forcer l'injection des standards normatifs officiels et des patterns DO/DON'T dans les agents IA avant l'écriture du code, éliminer le vibe coding par des contrats de sécurité explicites, et garantir l'auto-remédiation mécanique avant tout commit.

Ce que fait le système

Injonction Pré-Codage (Shift-Left)

Descriptions FastMCP forçant les LLMs à interroger KB dès la phase de planification avant d'écrire la moindre ligne.

Contrats de Sécurité par Stack

Packs normatifs (FastAPI/Supabase RAG, Next.js, Docker, CI) avec invariants absolus et checklist pré-codage.

CLI `kb init-guardrail`

Injecte automatiquement les règles de sécurité dans `.cursorrules`, `AGENTS.md` et `CLAUDE.md` de n'importe quel projet client.

Hook Git Pre-Commit `kb guard`

Garde-fou local ultra-rapide (< 100 ms) interceptant et bloquant tout commit contenant une violation critique.

Déjà opérationnel dans la base de code

  • 51 règles de sécurité actives vérifiées par le Grounding Judge avec 0 rejet (OWASP, RFCs).
  • Moteur de recherche sémantique pondéré par sévérité et intent matching (`kb search`).
  • Serveur FastMCP natif (stdio) avec audit instantané en mémoire (`audit_code_snippet`).
  • Packaging standalone Hatchling et distribution 1-ligne via uvx kb mcp.
  • Suite de 52 tests pytest validée à 100% sur GitHub Actions CI.

Hors-Périmètre v1

❌ Pas de dashboard web SaaS lourd : KB reste 100% CLI et FastMCP pour une exécution locale sans latence.

❌ Pas de proxy HTTP runtime : KB audite le code source, pas le trafic réseau en production.

❌ Pas d'autofix aveugle : L'agent ou le développeur doit toujours valider les propositions de remédiation.

❌ Pas de multi-tenant ou facturation : Conçu pour fonctionner sur les machines et runners CI de chaque projet.

Modèle de Données & Contrats

SecurityContract (Nouveau)

  • • stack_id : identifiant de stack technologique
  • • invariants : 3 à 5 règles d'or non négociables
  • • pre_coding_checklist : points de contrôle préalables
  • • do_patterns : exemples de code conformes prêts à injecter

GuardrailConfig (Nouveau)

  • • project_path : racine du projet inspecté
  • • detected_agents : .cursorrules, AGENTS.md, etc.
  • • pre_commit_hook_installed : statut du hook
  • • strict_mode : blocage sur sévérité critique

Jalons de Construction (Milestones)

Milestone 4 FastMCP & Contrats

Proactive Shift-Left MCP & Security Contracts

Rendre le serveur FastMCP impératif en amont (façon Context7) et implémenter les 4 contrats de sécurité normatifs par stack avec commande CLI kb contract.

Critère de fin : L'outil get_security_contract retourne un contrat structuré et la CLI liste les 4 contrats disponibles.
Milestone 5 CLI & Injonction

Project Guardrail CLI (`kb init-guardrail`)

Permettre au développeur d'injecter en 1 commande les directives de sécurité obligatoires dans les fichiers d'instructions d'agents (.cursorrules, AGENTS.md, CLAUDE.md) sans écraser les règles existantes.

Critère de fin : kb init-guardrail . --stack fastapi-supabase-rag injecte le bloc de sécurité délimité avec succès.
Milestone 6 Filet Git & Certificat

Git Pre-Commit Guard & Engineering Certificate (`kb guard` & `kb verify`)

Garde-fou mécanique local via hook git pre-commit ultra-rapide bloquant les commits défectueux, et certification formelle d'auditabilité pour documenter la conformité industrielle du projet.

Critère de fin : Le hook git intercepte un commit fautif et kb verify émet un certificat JSON et un badge de conformité vérifié.
